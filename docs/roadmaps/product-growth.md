# Long-term product-growth roadmap

## Vision

Clippity can become the **private visual workflow studio**: the fastest way to
capture something on screen, understand it, refine it, find it later and route
it into the user's work. Speed earns the first use; trusted local intelligence,
repeatable recipes and a memory of visual work earn retention and referrals.

## Current state

The product already has a differentiated overlay/editor and a local-first
technical story. It has no account, collaboration, growth loop, pricing model,
public release process or behavioral metric system. Feature breadth is ahead of
positioning: recording and multiple future settings are advertised before the
core journey is unified.

## Strengths to preserve

- Privacy-respecting default and no forced cloud/account.
- A visual identity and interaction quality people can recommend.
- Power-user surfaces (tray, presets, keybinds) that can compound retention.
- Structured provenance/library data that can support helpful intelligence.

## Problems and missed opportunities

- No defined north-star outcome, activation funnel or retention cohorts.
- No feedback loop, crash/support channel or beta/Labs program.
- No shareable output that naturally carries tasteful product attribution or
  reusable templates.
- Platform reach is Windows-only in practice.
- Cloud/team monetization could easily undermine the privacy differentiation if
  introduced carelessly.

## Personas and jobs

| Persona | Core job | Product promise |
| --- | --- | --- |
| Everyday user | Capture and send exactly what I mean. | Fast, obvious, no cleanup. |
| Creator/educator | Explain a visual process. | Beautiful annotation and narrative output. |
| Designer/developer | Extract UI evidence, colors, text and measurements. | Precise private visual inspection. |
| QA/support | Reproduce, compare and document issues repeatedly. | Recipes, provenance and visual diffs. |
| Team/admin | Keep visual knowledge secure and govern retention/sharing. | Optional encrypted collaboration with control. |

## Milestones and implementation phases

- **Short term:** positioning, G1–G2, private beta, activation/reliability cohort
  and ten workflow interviews per priority persona.
- **Mid term:** template/recipe loop, public Windows release, Pro-value tests and
  macOS technical spike.
- **Long term:** macOS GA, optional sync/team and extension marketplace only
  after trust, retention and operational maturity are proven.

Use problem interview → concierge/manual prototype → limited Labs cohort →
retention/value test → scalable implementation → pricing test → GA. Do not use
sign-up or clicks as proof that a complex feature deserves platform investment.

## Success criteria

- Activation ≥70%; week-8 retained-user rate improves ≥20% from first baseline.
- Weekly successful workflows per retained user and recipe reuse trend upward
  without increasing capture failure/support burden.
- Organic/referral acquisition ≥25% after public launch, driven by useful
  outputs/templates rather than coercive attribution.
- Privacy/trust sentiment ≥90% positive among surveyed active users.
- Paid conversion targets are met without removing essential local capture,
  export or accessibility capabilities from the free core.
- Each new platform reaches ≥99% core-capture success before parity claims.

## Risks, tradeoffs and alternatives

- Growth instrumentation can betray the privacy position; use coarse events,
  no capture content/titles by default, clear consent and a fully usable off
  state.
- Sync/team work can consume years; validate demand with encrypted export/import
  and shared packages first.
- A marketplace creates security/support obligations; signed first-party
  templates are a safer intermediate step.
- Monetizing basic accessibility, security or data portability would damage
  trust; keep them core capabilities.
