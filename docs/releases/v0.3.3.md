Clippity 0.3.3 is a documentation and cleanup release. It corrects the
developer documentation, tidies interface wording across the app and the
installer, and fixes a garbled character in a recording error message.

Still local-first: everything runs on your machine, no account, no cloud, and
the app sends no usage data anywhere.

This remains a **developer preview**. The binaries are unsigned; see
[Known gaps](#known-gaps).

## Downloads

| File                              | What it does                                                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **`Clippity-0.3.3-Setup.exe`**    | The full wizard: install, modify, repair, update, uninstall. One self-contained file with the app compiled into it. |
| **`Clippity-0.3.3-portable.zip`** | The application build. Unzip and run; no installer or registry entries, and settings stay beside the executable.    |
| `SHA256SUMS.txt`                  | Checksums for both release artifacts.                                                                               |

Because the binaries are unsigned, SmartScreen may show _"Windows protected
your PC"_ on first launch: **More info → Run anyway**. Verify the download
first if you prefer:

```text
certutil -hashfile Clippity-0.3.3-Setup.exe SHA256
```

**Requirements:** Windows 10 version 2004 (build 19041) or newer, and WebView2
(preinstalled on Windows 11).

## Changed

**Clearer interface wording**: messages, labels, and hints in the app and the
installer no longer use em dashes, and several read as plainer sentences. For
example, empty states such as _"No favorites yet. Star a capture to pin it
here."_, recording quality options such as _"Efficient (smaller files)"_, and
the installer's data choices _"(removed by default)"_ and _"(kept unless you
check it)"_.

**Accurate developer documentation**: the dev server port (1421), build
artifact paths, the Rust crate dependency graph, the command reference
(packaging, release, and benchmark commands), and the debugging guide now match
the code. The frontend's design-review pages, the recorder-frame window, and the
diagnostics under Settings → Advanced are documented, and the docs index covers
the installer, release notes, benchmarks, and UX-review tooling.

## Fixed

**Recording error text**: the Media Foundation message for an HDR frame that
does not match the recording geometry showed two garbled characters in place
of the `×` between its width and height.

**Release tooling**: `pnpm release:artifacts` now hashes each artifact as a
stream instead of reading it into memory, and the UX-review `snap.ps1 -FullScreen`
capture no longer fails in a fresh PowerShell session.

**Housekeeping**: removed an unused frontend dependency and an unused
component, and aligned the installer workspace's Node requirement (22.13+) with
the root workspace.

## Verification

- The full frontend suite (1,691 tests), TypeScript checks, lint, and
  production web builds pass for both the app and the installer.
- Every changed Rust source file passes rustfmt, and the installer domain tests
  pass. CI compiles, lints, and tests both Rust workspaces on Windows.
- Internal documentation links are checked, with none broken.
- The final Setup and portable artifacts are built from the tagged commit and
  checked against `SHA256SUMS.txt` before upload.

## Upgrading

Run `Clippity-0.3.3-Setup.exe` over an existing install. Existing settings,
captures, installation choices, and update preferences are preserved.

## Known gaps

- **Binaries are unsigned.** SmartScreen may warn on first run. Update downloads
  are protected by HTTPS plus the release asset's published SHA-256 digest, but
  Authenticode signing still requires a project signing certificate.
- **Automatic updates apply stable releases by default.** Developer-preview
  prereleases require selecting the Beta channel in the maintenance wizard.
- **HDR video depends on hardware/driver support.** Windows' built-in software
  HEVC encoder does not guarantee Main10/P010 input.
- **No Content Security Policy** is configured on the webview yet. The app loads
  no remote content and does not render raw HTML, but CSP remains planned
  hardening work.
