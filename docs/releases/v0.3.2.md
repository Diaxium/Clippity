Clippity 0.3.2 fixes startup appearance hydration so every window opens with the
user's saved theme instead of waiting for focus or another UI interaction.

Still local-first: everything runs on your machine, no account, no cloud, and
the app sends no usage data anywhere.

This remains a **developer preview**. The binaries are unsigned; see
[Known gaps](#known-gaps).

## Downloads

| File                              | What it does                                                                                                         |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **`Clippity-0.3.2-Setup.exe`**    | The full wizard — install, modify, repair, update, uninstall. One self-contained file with the app compiled into it. |
| **`Clippity-0.3.2-portable.zip`** | The application build. Unzip and run; no installer or registry entries, and settings stay beside the executable.     |
| `SHA256SUMS.txt`                  | Checksums for both release artifacts.                                                                                |

Because the binaries are unsigned, SmartScreen may show _"Windows protected
your PC"_ on first launch — **More info → Run anyway**. Verify the download
first if you prefer:

```text
certutil -hashfile Clippity-0.3.2-Setup.exe SHA256
```

**Requirements:** Windows 10 version 2004 (build 19041) or newer, and WebView2
(preinstalled on Windows 11).

## Fixed

**Saved themes now apply at startup** — backend state is initialized before any
WebView can request settings, eliminating the race that left the initial
settings request without managed state. The frontend also hydrates the saved
theme, accent, motion preference, and icon choice before mounting React, so the
first rendered frame already matches the user's appearance settings.

**Hidden utility windows stay consistent** — windows created hidden at launch,
including the tray, toast, countdown, overlay, and recorder frame, receive the
same pre-render appearance hydration and no longer depend on a later focus or
visibility event.

## Verification

- Startup appearance tests cover explicit themes, System theme resolution,
  accent contrast, reduced motion, icon state, and the no-settings fallback.
- The full frontend suite, TypeScript checks, lint, and production web builds
  pass.
- Both Rust workspaces pass formatting, compilation, warnings-as-errors clippy,
  and their full test suites.
- The final Setup and portable artifacts are built from the tagged commit and
  checked against `SHA256SUMS.txt` before upload.

## Upgrading

Run `Clippity-0.3.2-Setup.exe` over an existing install. Existing settings,
captures, installation choices, and update preferences are preserved.

## Known gaps

- **Binaries are unsigned.** SmartScreen may warn on first run. Update downloads
  are protected by HTTPS plus the release asset's published SHA-256 digest, but
  Authenticode signing still requires a project signing certificate.
- **Automatic updates apply stable releases by default.** Developer-preview
  prereleases require selecting the Beta channel in the maintenance wizard.
- **HDR video depends on hardware/driver support.** Windows' built-in software
  HEVC encoder does not guarantee Main10/P010 input.
- **No Content Security Policy** is configured on the webview yet. The app loads
  no remote content and does not render raw HTML, but CSP remains planned
  hardening work.
