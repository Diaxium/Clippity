Clippity 0.3.1 completes the Windows installer's **update and maintenance
system** and connects its choices all the way through to the installed app.

Still local-first: everything runs on your machine, no account, no cloud, and
the app sends no usage data anywhere.

This remains a **developer preview**. The binaries are unsigned; see
[Known gaps](#known-gaps).

## Downloads

| File                              | What it does                                                                                                         |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **`Clippity-0.3.1-Setup.exe`**    | The full wizard — install, modify, repair, update, uninstall. One self-contained file with the app compiled into it. |
| **`Clippity-0.3.1-portable.zip`** | The application build. Unzip and run; no installer or registry entries, and settings stay beside the executable.     |
| `SHA256SUMS.txt`                  | Checksums for both release artifacts.                                                                                |

Because the binaries are unsigned, SmartScreen may show _"Windows protected
your PC"_ on first launch — **More info → Run anyway**. Verify the download
first if you prefer:

```text
certutil -hashfile Clippity-0.3.1-Setup.exe SHA256
```

**Requirements:** Windows 10 version 2004 (build 19041) or newer, and WebView2
(preinstalled on Windows 11).

## New

**Real update delivery** — the maintenance tool discovers releases from the
selected stable, beta, or nightly channel, chooses the newest semantic version,
downloads its self-contained Setup executable, verifies its exact byte count and
GitHub-published SHA-256 digest, then applies the new embedded payload through
the same journaled transaction used by install and modify.

**Automatic updates** — managed installations check at most once per day when
the app starts. A verified update waits for Clippity to exit, applies itself,
and relaunches the app. Turning automatic updates off in either Setup or the
app's Settings is respected.

**Windows file associations** — Setup can add Clippity to **Open with** for PNG,
JPEG, WebP, GIF, BMP, and MP4 without replacing the user's default apps. Opening
one of those files routes images to Editor and video to Studio.

## Improvements

**Wizard choices now take effect** — desktop shortcuts, start at login,
automatic updates, file associations, optional capture/OCR/GIF capabilities,
scope, and destination are persisted and reconciled by install, modify, repair,
update, and the installed app. Modify preserves app-side preference changes and
cannot accidentally move or change the scope of an existing installation.

**Data-aware uninstall** — application files and integrations are always
removed; cache, settings/presets, and local captures/projects are independent
choices. Personal content remains opt-in, unsafe recursive roots are rejected,
unknown files in an install directory are preserved, and settings export writes
a portable JSON backup before removal.

**Honest maintenance UI** — update checks use the installed manifest and live
release data, reminder deferrals persist for one week, scheduled updates say
they are scheduled, maintenance metadata is no longer hard-coded, background
failures surface in the progress screen, and **Open settings** routes to the
actual Settings view.

**Recovery hardening** — updates preserve the installation identity and prior
configuration, installer self-replacement is rollback-safe, payload write
failures restore the old executable immediately, and repair re-registers file
associations from the committed manifest.

## Verification

- Installer domain and service suites cover version/channel selection, digest
  rejection, transactions and rollback, repair, removal safety, independent
  data-category cleanup, unsafe path rejection, CLI parsing, and recovery.
- Both Rust workspaces pass formatting, compilation, clippy, and tests.
- Both TypeScript workspaces pass type-checking; the app frontend test suite and
  production builds pass.
- The final Setup and portable artifacts are built from the tagged commit and
  checked against `SHA256SUMS.txt` before upload.

## Upgrading

Run `Clippity-0.3.1-Setup.exe` over an existing install. Future updates can then
be installed from the maintenance wizard or automatically after Clippity exits.
Existing settings and captures are preserved.

## Known gaps

- **Binaries are unsigned.** SmartScreen may warn on first run. Update downloads
  are protected by HTTPS plus the release asset's published SHA-256 digest, but
  Authenticode signing still requires a project signing certificate.
- **Automatic updates apply stable releases by default.** Developer-preview
  prereleases require selecting the Beta channel in the maintenance wizard.
- **HDR video depends on hardware/driver support.** Windows' built-in software
  HEVC encoder does not guarantee Main10/P010 input.
- **No Content Security Policy** is configured on the webview yet. The app loads
  no remote content and does not render raw HTML, but CSP remains planned
  hardening work.
